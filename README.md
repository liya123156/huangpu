# 黄浦大区｜组织管理与人效工作台 V3.1

以目标和活动量找到重点组与人，把复盘结论落到提升方向、管理者支持、待办及复查。公开仓库只保存程序，不提交人员名单、入职日期、业绩明细、沟通记录、私有备份或密钥。

## 四个模块

1. 活动量看板：大区—门店—店组—个人；表头增删、改名、排序；表格复制／下载图片。
2. 重点组和人：绩效×活动量四象限；入职日期及0–6、6–12、12–24、24个月以上司龄结构。
3. 提升方向及待办：风险排查、目标牵引、赋能、激发、标杆分享、阶段答疑和岗位适配／退出建议；负责人、截止与复查日期、实际变化及修改历史。
4. 数据导入：所有Excel/CSV、人员表和完整备份从同一入口进入。截图仅预览，未接自动识别。

市场与市占、带看流向不再显示，也不再作为新的导入用途。兼容代码保留旧备份数据，不删除历史。

## 默认评选标准与可修改规则

实际业绩严格大于0为高绩效；明确的0为低绩效。无需先录业绩目标。缺失、负数调整、周期不一致均待核，不当作0。

活动量默认选择带看量和重点渠道新增。单项直接排名；多项先计算各项百分位名次，再按权重求平均分，不将不同单位数量直接相加。仅完整、同周期对象进入活动量比较；缺绩效者仍可参与有依据的活动量排名，但不进入四象限。未提供的其他业务指标不被替代。

高活动量默认前50%，其余为低。店组和个人分别排名，可按当前筛选范围或固定全大区比较。司龄仅筛选显示，不改变分母。人数为奇数向上取整；临界同分可设全部归高、全部归低或待确认，因而人数未必恰好各半。全部同分或不足2个可比对象不强行分类。

在“修改评选标准”可改绩效指标、运算符、分界、活动指标、权重、百分比、范围及同分规则。保存即重算名单，并保留规则历史。

四象限是组织管理的线索，不是自动人员处置。风险对象应及时核实、沟通及提供合适支持。岗位适配／退出建议需结合事实、本人反馈与管理者／HR确认，不生成自动淘汰名单。司龄不直接决定人员处置。

## 一次性开通网页

代码位于main分支根目录，无需构建。仓库的程序提交与网页发布是不同状态。

在仓库 Settings -> Pages 中选择 Deploy from a branch，Branch选main，目录选/(root)，点击Save。待GitHub Pages显示部署成功后，使用其返回的站点地址。此仓库对应的预期地址为 https://liya123156.github.io/huangpu/ 。在开启并验证之前，不应把预期地址称作可用线上链接。

此操作只发布代码，不发布本地业务数据。后续main分支更新会由所选发布源自动发布。GitHub Actions的Validate and package dashboard验证代码并打包，**不是部署成功证明**。

## 数据与保存

沿用同一浏览器来源下的 IndexedDB `huangpu_repository_v3`，兼容旧版v2/v3完整备份、表头和跟进记录。初次切换到新的域名或浏览器，需要在数据导入中恢复私有完整备份一次。恢复是替换，先导出当前资料。仅“已保存到本机”才表示本机保存成功。

创建待办时保留当时的规则、数据周期和关联对象快照；修改标准不改写历史快照。历史待办字段继续兼容。可导出包含新增字段与修改历史的完整JSON备份。

当前没有云端数据同步、账户权限、网页内AI、自动截图识别或微信发送。所有解析与排名在本机进行。不应把本机保存当成账号隔离或云端备份。原始业务信息不得写进公开GitHub仓库。
