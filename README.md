# 黄浦大区｜组织管理与人效工作台 V3.9.1

以目标和活动量找到重点组与人，把复盘结论落到提升方向、管理者支持、待办及复查。公开仓库只保存程序，不提交人员名单、入职日期、业绩明细、沟通记录、私有备份或密钥。

## 四个模块

1. 活动量看板：最近三个月的门店—店组—个人数量对比，全部层级直接展示；活动指标表头左右拖动；整店看板复制／保存图片；店内标杆与重点提醒。
2. 重点组和人：绩效×活动量四象限；入职日期及0–6、6–12、12–24、24个月以上司龄结构。
3. 提升方向及待办：风险排查、目标牵引、赋能、激发、标杆分享、阶段答疑和岗位适配／退出建议；负责人、截止与复查日期、实际变化及修改历史。
4. 数据导入：所有Excel/CSV、人员表和完整备份从同一入口进入。截图仅预览，未接自动识别。

市场与市占、带看流向不再显示，也不再作为新的导入用途。兼容代码保留旧备份数据，不删除历史。

## 默认评选标准与可修改规则

实际业绩严格大于0为高绩效；明确的0为低绩效。无需先录业绩目标。缺失、负数调整、周期不一致均待核，不当作0。

活动量默认选择带看量和重点渠道新增。单项直接排名；多项先计算各项百分位名次，再按权重求平均分，不将不同单位数量直接相加。仅完整、同周期对象进入活动量比较；缺绩效者仍可参与有依据的活动量排名，但不进入四象限。未提供的其他业务指标不被替代。

高活动量默认前50%，其余为低。店组和个人分别排名，可按当前筛选范围或固定全大区比较。司龄仅筛选显示，不改变分母。人数为奇数向上取整；临界同分可设全部归高、全部归低或待确认，因而人数未必恰好各半。全部同分或不足2个可比对象不强行分类。

在“修改评选标准”可改绩效指标、运算符、分界、活动指标、权重、百分比、范围及同分规则。保存即重算名单，并保留规则历史。

四象限是组织管理的线索，不是自动人员处置。风险对象应及时核实、沟通及提供合适支持。岗位适配／退出建议需结合事实、本人反馈与管理者／HR确认，不生成自动淘汰名单。司龄不直接决定人员处置。

## 一次性开通网页

代码位于main分支根目录，无需构建。仓库的程序提交与网页发布是不同状态。

在仓库 Settings -> Pages 中选择 Deploy from a branch，Branch选main，目录选/(root)，点击Save。待GitHub Pages显示部署成功后，使用其返回的站点地址。此仓库对应的预期地址为 https://liya123156.github.io/huangpu/ 。在开启并验证之前，不应把预期地址称作可用线上链接。

此操作只发布代码，不发布本地业务数据。后续main分支更新会由所选发布源自动发布。GitHub Actions的Validate and package dashboard验证代码并打包，**不是部署成功证明**。

## 数据与保存

编辑端沿用 IndexedDB `huangpu_repository_v3` 作为本机保存，兼容旧版v2/v3完整备份、表头和跟进记录。通过私有编辑入口接入后，将活动量看板结果自动同步到云端。原始底表、名册和HR待办继续保存在本机；更换编辑设备时仍需私下导出／恢复完整备份。“已保存到本机”与“看板已同步”是两个状态。

创建待办时保留当时的规则、数据周期和关联对象快照；修改标准不改写历史快照。历史待办字段继续兼容。可导出包含新增字段与修改历史的完整JSON备份。

共享链接通过云端读取活动量投影，不需要每人重新导入。云端仅保存活动量看板投影和版本校验信息，分享端只能读取活动量，看不到原始底表、工号、入职日期和HR待办。当前使用独立的私有编辑链接和只读分享链接，不是员工账号登录；持有链接即拥有对应权限。网页内AI、自动截图识别和微信发送尚未接入。原始业务信息和访问凭据不得写进公开GitHub仓库。

### 后端部署

使用 Supabase 项目中的独立 `hp_shared_workspaces` 表与 `huangpu-share-sync` Edge Function。建表参考 `supabase/schema/huangpu-sharing.sql`，不会更改其他工作台。RLS开启且撤销 `PUBLIC`、`anon`、`authenticated` 表权限，Edge Function 使用服务器环境中的 service-role 访问数据库。

函数采用自定义 `x-hp-token` 鉴权，部署时仅该函数设置 `verify_jwt=false`。读写令牌各使用32字节加密随机值的 base64url 表示，数据库只保存 UTF-8 令牌字符串的 SHA-256。配置文件 `assets/shared-config.js` 仅包含公开 endpoint 和 workspace，不包含访问令牌。

GET返回该角色允许的单个gzip/base64信封（带压缩字节SHA-256）；PUT必须是编辑权限，携带 `expectedRevision`、`state`、`published`，按revision原子比较更新。`state` 仅允许格式标识、活动量投影摘要hash、来源更新时间三项版本信息，服务端拒绝完整备份；`published` 解压后为白名单活动量DTO。只读分享链接使用 `?share=...#activity` 并保留在查看者地址栏，兼容旧版 fragment 入口；编辑入口仍只用 fragment，进入后清除编辑凭据。页面设置 `no-referrer`，避免把查看入口带给外部页面；编辑凭据和同步状态不进入业务备份。只读令牌不写入公开仓库。

同一 GitHub Pages 账号下的仓库共享 origin；编辑凭据属于该 origin 的安全边界。不要引入不受信任的同源脚本，也不要将私有编辑入口转发同事。需要撤销权限时，在服务端更换对应令牌hash并重新发放入口。
